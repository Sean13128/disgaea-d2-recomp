AP fixed the startup queue race and reproduced/fixed ATRAC seek-to-loop failures. The exact user's map30005 round trip still needs real-Mac confirmation; plain same-handle track switches alone did not fail in the CPU harness.

Root causes:

- **Muted-start stall was a scheduling race, not gain scaling.** Static SurMixer Start (`00306474`, key load at `0030650C`) could run before `_cellsurMixerMain` (`00308234`) published `state+0x500` and created its queue. The SDK accepted zero and resolved it to an unrelated local SPU event queue. Settings altered scheduling enough to expose it. A version-140 D2 override waits up to two seconds for the actual published key/queue; SDK cellAudio rejects zero and duplicate registrations and synchronizes notification-table reads. Gain remains output-only. RPCS3 independently has a workaround for this same `_cellsurMixerMain`/`_mxr000` race: [AudioSetNotifyEventQueue](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellAudio.cpp).
- **Streaming ATRAC mistook a cached EOF tail for a resident looping track.** It returned `-2`, causing D2 (`00160C68`) to skip refills. At the loop seam, Decode returned NODATA; D2 retires the line on any Decode error (`00160BF4`). GetNextDecodePosition also falsely returned ALLDATA at looping EOF. The old runtime reproduces both with the actual hub file after a tail seek.
- **Only retaining the latest seek range was insufficient.** Loop prefetch discarded the still-playing cached tail and produced another NODATA. The cache now retains and merges all submitted intervals. Streaming reports `-3` only when loop data including preroll is resident, keeps positive remaining frames for sparse tails, and redirects EOF refill to missing loop data before Decode reaches it. EOF position/sample queries respect looping. SetData clears the prior track's ring/cache/reset state.
