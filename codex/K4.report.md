# K4 — movie feed/completion handshake

Fixed two generic SDK demux races. The lifted game now completes the movie with synthetic VT output paced at 24 fps and 5–15 ms decode latency. **Real-VT confirmation of the original picture-353 stall still requires the host rerun**; sandbox VT returns `-12911`.

## Root causes

- **DEMUX_DONE was sent while the demux was still BUSY.** NisMovieDmux consumes the completion event, attempts the next SetStream, gets BUSY, clears its local ready flag and waits for another completion that cannot occur. The worker now publishes idle before notification, owns its input buffer locally, and preserves refills queued during the callback. A separate `working` flag keeps ResetStreamAndWaitDone from resetting the parser while a completion callback is still running. RPCS3 likewise sets DMUX_STOPPED before calling DEMUX_DONE (read through `gh`).
- **Audio and video FlushEs shared one busy command slot.** At EOF the second decoder thread received `0x80610203`, reported a fatal movie-thread error and aborted the remaining pictures/PCM. ES flushes now queue independently, without marking the stopped stream busy, and each receives FLUSH_DONE.

The old code's completion window was widened temporarily by 10 ms after stream 11's callback. With burst decode latency this reproduced the drained-backlog stall at **picture 359**, rather than exactly 353: video found/get/released=360, audio=350, both queues empty, submitted/completed=5,767,168 bytes, and no subsequent stream. The same probe with the fix reached picture 949 within 40 seconds. Uniform latency/24-fps pacing alone did not reproduce the original stall before the fix. The temporary production delay probe was removed; the callback regression retains a delayed return in its test harness.

## Files changed

Only SDK `libs/codec/`: `cellDmux.c`, `pamf_demux.c/.h`, `cellAdec.c`, `cellVdec.c`, `tests/test_movie.cpp`, `tests/test_vt_mock.cpp`, new `tests/test_dmux_handshake.cpp`. Also the requested `codex/K.host-check.sh` and this report. No game override, dump, other build directory, CMake, commit or push changes.

`PS3RECOMP_CODEC_TRACE=1` reports stream submissions/completions and parsed bytes, per-ES found/acquired/released AUs, blocked/idle queues, decoder callback entry/return, video jobs/worker state, and audio accepted/completed/consumed counts. Host checks now require exact stream/ES/PCM totals and save `K4-host.*` artifacts.
